# AGV × Cosmos 실험 정리 — 월드모델로 충돌을 미리 볼 수 있을까

2026.09.16 ~ 10.02 · 정리: 김철호 · 팀 공유용

---

## 한 줄 요약

**Cosmos는 AGV가 장애물로 직진해도 부딪히는 미래를 한 번도 그리지 않았습니다(50번 중 0번).** 모델이 학습 데이터에서 "앞의 물체에는 닿지 않는다"는 습관을 배웠기 때문입니다. 같은 데이터로 처음부터 학습시킨 **Dreamer는 50번 중 39번 충돌을 그렸습니다.** 다만 처음 보는 물체는 아는 물체로 바꿔 그렸습니다.

---

## 1. 무엇을 하려 했나

- **과제(교수님 제안):** Isaac Sim + Cosmos를 AGV 주행에 활용하기
- **아이디어:** AGV가 움직이기 전에 Cosmos로 "이대로 가면 어떻게 될지"를 영상으로 상상해 보고, 상상 속에서 부딪히면 미리 멈춘다.
- **확인할 것:** Cosmos의 상상이 실제와 맞는가? Isaac Sim에서 같은 장면을 실제로 달려 보면 정답을 알 수 있으니, 상상과 정답을 비교한다.

## 2. 실험 환경

| 장비 | 역할 | 이유 |
|---|---|---|
| RTX 5090 가상머신 | Isaac Sim 6.1 — 주행 장면과 정답 영상 생성 | 화면을 그릴 때 레이트레이싱 코어(RT 코어)가 필요 |
| Jetson AGX Orin 64GB | Cosmos 3 Nano(160억 파라미터) — 미래 영상 생성, 추가 학습, Dreamer 학습 | 영상 한 편 생성에 메모리 약 34GB 필요 (5090은 32GB라 부족) |
| 맥북 | Isaac 화면 원격 확인 | 연구실 망이 스트리밍 포트를 막아 Tailscale(VPN)로 접속 |

**Isaac Sim 장면**
- 기본 창고(Simple_Warehouse)에 물류 AGV(iw.hub)를 둡니다. 카메라는 AGV 앞쪽 **높이 25cm**, 640×480입니다.
- 장애물은 창고 소품 5종(상자 2종, 플라스틱 통 3종) 중 하나를 **1.0~1.6m 앞**에 무작위로 놓습니다.
- AGV는 1m/s로 0.5초 달린 뒤의 화면을 "첫 화면"으로 쓰고, 이후 2초를 기록합니다.
  - **직진:** 1m/s 유지, 닿으면 비상 정지
  - **정지:** 1m/s²로 감속해서 장애물 앞에서 섬

**Cosmos 사용법 (forward dynamics)**
- 첫 화면 1장과 앞으로의 움직임(명령)을 주면, 그렇게 움직였을 때의 영상을 **1.6초** 만들어 줍니다.
- 명령은 자율주행(av) 형식으로 줍니다. 전진 값 0.83이 1m/s에 해당하는 것을 미리 재서 맞췄습니다.
- 한 편 만드는 데 약 1.8분 걸립니다.

## 3. 실험 방법 — 2×2 설계

| | 직진 명령 | 정지 명령 |
|---|---|---|
| **장애물 있음** | 정답: 부딪힌다 ← **핵심 질문** | 정답: 앞에서 선다 |
| **빈 길** (대조군) | 정답: 그냥 간다 | 정답: 선다 |

- **장면:** 장애물 위치와 종류를 바꾼 50개
- **채점:** Cosmos가 상상한 영상이 실제 '직진 결말'과 '정지 결말' 중 어느 쪽과 더 닮았는지 봅니다. 같은 시각의 화면 25장을 작은 흑백 이미지로 비교합니다.
- **대조군의 역할:** 빈 길에서 명령을 잘 따르면, "Cosmos가 명령을 무시한다"가 아니라 "장애물이 있을 때만 문제"라는 것을 보여 줍니다.

## 4. 결과 — 진행 순서대로

### 4-1. 본실험 (9/24): 충돌을 한 번도 그리지 않았다

| | 직진 명령 | 정지 명령 |
|---|---|---|
| 장애물 | **0/50** | 50/50 |
| 빈 길 | 50/50 | 50/50 |

명령은 잘 따랐지만, 장애물로 직진시키면 50번 모두 부딪히지 않는 미래를 그렸습니다.

### 4-2. 원인 확인: 장애물이 로봇과 같이 물러났다

- 장애물 부분을 가리고 **배경만** 실제 영상과 비교했더니, 50/50 모두 로봇은 명령대로 1m/s로 앞으로 갔습니다.
- 그런데 장애물은 다가오지 않았습니다. 로봇이 가는 만큼 **장애물도 같이 물러난** 것입니다.
- 명령을 세게 주면 통이 **로봇으로 바뀌어 멀어지는** 장면도 나왔습니다.

### 4-3. 설정을 바꿔 봤다: 그래도 안 됐다

| 바꾼 것 | 결과 |
|---|---|
| 명령(전진 값)을 훨씬 세게 | 충돌 없음. 속도는 약 1.4m/s에서 더 오르지 않음 |
| 문장으로 알려 주기 ("물체는 멈춰 있다", "부딪힌다" 등 3종) | 충돌 없음 |
| 무작위 시작값(seed) 변경 | 충돌 없음 |
| 행동 형식 변경 (자율주행 → 카메라 이동) | 충돌 없음 |
| Cosmos에게 직접 운전시키기 (policy) | 장애물 앞에서도 거의 전속 직진을 고르고, 영상 속 장애물은 물러남 |
| 직전 0.53초 실제 영상을 주고 이어 그리기 | 충돌 없음 (로봇이 멈추거나, 상자가 로봇으로 바뀌거나, 덜 다가옴) |

→ 설정 문제가 아니라 **모델 자체의 습성**이라고 판단했습니다.

### 4-4. 그래서 가르쳐 봤다: Cosmos 추가 학습 (9/28~9/30)

- Isaac에서 학습용 장면 500개를 새로 만들어, Cosmos에 작은 부품(LoRA, 전체의 0.1~0.3%)을 붙여 학습시켰습니다.
- 처음 보는 물체에도 통하는지 보려고 **빨간 통**은 학습에서 뺐습니다.

| 차수 | 방법 | 장애물+직진 충돌 (10장면) |
|---|---|---|
| 1차 | 영상 생성 부분만 학습 | 1/10 |
| 2차 | 학습 범위 확대 + 출발 위치 다양화 | 0/10 |
| 3차 | **같은 장면의 직진·정지 영상을 짝지어** 학습 | **3/10** |

- 3차에서 처음 충돌이 나왔지만 **학습한 통에서만** 나왔습니다. 처음 보는 빨간 통과 상자는 0이었습니다.
- 대신 장애물이 물러나지 않고 "멈춘 물체"로 그려지기 시작했습니다.
- 주의할 점: 학습한 모델은 문장 증폭(guidance)을 6이 아닌 1로 써야 효과가 제대로 나옵니다.

### 4-5. 카메라를 AGV 뒤로 (9/30)

- 카메라를 AGV 뒤 2m, 높이 0.7m에 두어 차체가 보이게 하자, 원래 Cosmos로도 **상자 장면 4/5**에서 충돌 비슷한 장면이 나왔습니다. 통은 0/5였습니다.
- 해석: 범퍼 높이 카메라로 보면 충돌은 "화면이 꽉 막히는" 드문 장면이지만, 뒤에서 보면 "두 물체가 만나는" 흔한 장면입니다. 다만 10장면뿐이라 근거가 약합니다.

### 4-6. 더 확인해 봤다: 길게 해도, 상대가 와도 안 부딪힌다 (9/30)

| 시험 | 실제 | Cosmos |
|---|---|---|
| 이어 그리기를 **5초**로 길게 | 부딪힘 | 1초쯤 **상자가 지게차로 바뀌어** 앞으로 달려감 |
| AGV는 멈춰 있고 **지게차가 1.5m/s로 다가옴** (브레이크 없음) | **1.7초에 충돌** | 지게차가 **스스로 멈추고**, 조금 물러났다가 천천히 다가옴. 브레이크등 같은 불빛까지 켬 |

→ 부딪히는 대신, **움직일 수 있는 쪽이 비켜 줍니다.** 상자는 차가 되어 달아나고, 지게차는 스스로 섭니다.
→ AGV에게 가장 위험한 경우에 "괜찮다"고 상상하는 셈입니다.

### 4-7. Dreamer와 비교 (10/1, 교수님 제안)

- **Dreamer란:** Google DeepMind 연구진이 만든 월드모델입니다(DreamerV3, 2025 Nature). 완성품인 Cosmos와 달리 **자기 환경 데이터로 처음부터** 학습합니다.
- **설정:** Cosmos 추가 학습과 **같은 Isaac 데이터**로 처음부터 학습시켰습니다. 크기는 1,570만 파라미터(Cosmos의 약 1/1000), 화면은 64×64, 학습에는 Orin에서 약 2.5시간 걸렸습니다.

| | Cosmos 원래 | Cosmos 추가 학습 | **Dreamer** |
|---|---|---|---|
| 장애물+직진 충돌 | 0/50 | 3/10 | **39/50** |
| 학습한 물체 | — | 3/8 | **39/39** |
| 처음 보는 빨간 통 | 0 | 0/2 | 0/11 |
| 대조군 (정지, 빈 길) | 50/50 | 10/10, 빈 길 직진 8/10 | **모두 50/50** |

- 학습한 물체에서는 직진하면 화면이 물체로 꽉 차고(충돌), 정지하면 앞에서 섭니다. 실제와 거의 같습니다.
- **처음 보는 빨간 통은 상자로 바꿔 그린 뒤 그 상자에 부딪혔습니다.** 움직임은 맞지만 물체가 틀려서 채점에서는 0이 나왔습니다. 본 것만 압니다.

## 5. 왜 Cosmos는 안 됐나

1. **입력에 빈칸이 있습니다.** 우리는 로봇의 움직임(명령)만 줬고, 장애물이 멈춰 있는지는 알려 주지 못했습니다. 사진 한 장에는 속도가 없습니다.
2. **모델이 빈칸을 습관으로 채웁니다.** Cosmos가 배운 영상에서 앞의 물체는 대개 같이 달리는 앞차였습니다. NVIDIA 설명서에도 학습 데이터에서 '위험한 조작'을 걸러 냈다고 적혀 있습니다. 그래서 "앞의 물체에는 닿지 않는다"는 습관이 생겼습니다.
3. **설정·문장으로는 습관을 못 바꿉니다.** 문장은 이미 가능한 결말 중에서 고를 뿐, 배운 적 없는 결말(충돌)을 만들지 못합니다.
4. **다른 연구에서도 같은 현상이 보고됐습니다.** '낙관 편향'이라고 부르며, 실패할 행동에도 성공하는 미래를 그리는 버릇입니다. 여러 모델에 공통이고, 모델을 키워도 고쳐지지 않았습니다(MiraBench, 2026).
5. **Dreamer 결과가 이를 뒷받침합니다.** 같은 데이터를 줘도 습관이 없는 Dreamer는 충돌을 배웠습니다. 문제는 데이터가 아니라 Cosmos가 미리 배운 습관이었습니다.

## 6. 결론과 다음 방향

**결론**
1. 지금 그대로의 Cosmos는 AGV 충돌 예측에 쓸 수 없습니다.
2. 원인은 설정이 아니라 모델의 습성입니다. 모르는 장애물 움직임을 "안 부딪힘"으로 채웁니다.
3. Cosmos를 작게 추가 학습해서는 일부만 개선됐습니다(10개 중 3개, 배운 물체만).
4. 같은 데이터로 학습한 Dreamer는 50번 중 39번 충돌을 그렸습니다. 단, 본 물체만입니다.

**다음 방향 (10/6 교수님 미팅에서 논의)**
- 충돌 판단은 그 환경에서 배운 모델(Dreamer 등)이나 거리 계산이 맡는다.
- Cosmos는 겉모습을 맡는다. Isaac 화면을 사실적으로 바꿔 학습 데이터로 쓰는 방향이며, NVIDIA 공식 경로입니다(아직 검증 안 함).
- Dreamer의 "본 것만 안다"를 넘으려면 물체를 다양하게 하고, 다가오는 장애물이나 실제 영상으로 확인해야 합니다.

## 8. 용어

| 용어 | 뜻 |
|---|---|
| 월드모델 | 지금 장면과 행동을 주면 다음 장면을 상상해 주는 AI |
| forward dynamics | 첫 화면 + 앞으로의 움직임 → 미래 영상 |
| 대조군 | 결과를 해석하기 위한 기준 조건 (여기서는 빈 길, 정지 명령) |
| LoRA | 원래 모델은 얼려 두고 작은 부품만 붙여 학습하는 방법 |
| guidance | 문장의 영향을 몇 배로 키울지 정하는 값 |
| seed | 영상 생성을 시작할 때의 무작위 값 |
| 낙관 편향 | 실패할 행동을 줘도 성공하는 미래를 그리는 월드모델의 버릇 |
