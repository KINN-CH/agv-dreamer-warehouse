AGV Dreamer 수식 노트

깊이 카메라 값이 2D 지도가 되고, Dreamer가 그것으로 2초 뒤를 상상해 속도를 고르기까지 — 우리 시스템에 쓰인 식을 모두 적고, 식마다 쉬운 말과 실제 숫자를 붙였습니다. 숫자는 최종 모델(v5c)과 실제 코드 기준입니다.

깊이 값→3D 점→점 고르기→64×64 칸→행동→Dreamer→학습→상상·속도 ·규칙길찾기평가한계

1깊이 카메라가 주는 값

깊이 카메라는 픽셀마다 거리 숫자 하나를 줍니다. 화면의 빨강~파랑은 사람이 보라고 칠한 것이고, 계산에는 숫자만 씁니다.

\[ Z = D(u, v)\quad [\mathrm{m}],\qquad u = 0..159,\ \ v = 0..119 \]

픽셀 하나가 어느 방향을 보는지는 카메라의 초점 거리(픽셀 단위)로 정해집니다.

\[ f_x = f_y = \frac{f}{A}\,W = \frac{6.0}{20.955}\times 160 \approx 45.8\ \text{px},\qquad c_x = 80,\ \ c_y = 60 \] \[ \text{FOV}_{\text{horizontal}} = 2\arctan\frac{W/2}{f_x} = 2\arctan\frac{80}{45.8} \approx 120^\circ,\qquad \text{FOV}_{\text{vertical}} \approx 105^\circ \]
쉬운 말\(f\)는 렌즈 초점 거리, \(A\)는 센서 가로 폭(Isaac Sim 기본 20.955), \(W\)는 가로 픽셀 수입니다. \(f_x\)가 작을수록 넓게 봅니다. \((c_x, c_y)\)는 화면 한가운데입니다.

실제 RealSense는 픽셀마다 정수(1mm 단위)를 줍니다. 1520 → 1.52m. 형식은 같고, 실제 카메라는 잡음과 빈 값(0)이 있습니다(→ 한계).

2픽셀 하나를 3D 점으로 (핀홀 카메라 식)

\[ X = \frac{(u - c_x)\,Z}{f_x},\qquad Y = \frac{(v - c_y)\,Z}{f_y} \]
쉬운 말"화면 가운데에서 몇 픽셀 떨어졌나" × 거리 ÷ 초점 = 실제로 옆(아래)으로 몇 m 떨어졌나. 닮은 삼각형 비율입니다. \(X\)는 카메라 기준 오른쪽, \(Y\)는 아래쪽입니다.

이것을 AGV 기준(앞·왼쪽·높이)으로 옮깁니다. 감지 카메라는 차체 기준점보다 0.36m 앞, 바닥에서 \(h_c\) 높이에 있고 정면을 봅니다.

\[ x_f = 0.36 + Z,\qquad x_l = -X,\qquad x_h = h_c - Y,\qquad h_c \approx 0.33\ \text{m} \]
예시 (7장 그림과 같은 순간): 사람 몸의 한 픽셀 (u, v) = (88.5, 52.5), Z = 1.71m
→ X = 0.32, Y = −0.28 → 앞 2.07m · 왼쪽 −0.32m(오른쪽 0.32m) · 높이 0.61m

옆·뒤 카메라 3대(차체 옆면 ±90°, 뒷면 180°)도 같은 식을 쓰고, 카메라 방향만큼 돌려서 같은 AGV 기준으로 모읍니다. 실제 코드에서는 Isaac Sim이 점을 창고(월드) 좌표로 주므로, AGV 위치 \((x, y)\)와 방향 \(\psi\)로 다시 AGV 기준으로 돌립니다.

\[ x_f = \cos\psi\,(X_w - x) + \sin\psi\,(Y_w - y),\qquad x_l = -\sin\psi\,(X_w - x) + \cos\psi\,(Y_w - y) \]
쉬운 말창고 지도 위의 점을 "AGV가 바라보는 방향이 위"가 되게 돌려 놓는 식입니다. 결과는 위 식과 같습니다.

3점 고르기 — 높이와 거리

\[ d = \sqrt{x_f^2 + x_l^2} \] \[ \text{obstacle: } 0.1 \lt x_h \lt 1.0\ \text{ and } d \lt 5,\qquad \text{floor: } x_h \lt 0.05\ \text{ and } d \lt 5,\qquad \text{else: drop} \]
쉬운 말 장애물 = 바닥에서 10cm~1m 높이에 있는 점(AGV가 부딪힐 수 있는 높이). 바닥 = 높이 5cm 아래 점(“여기는 비어 있다”는 증거). 1m보다 높은 점(천장·랙 윗단), 5m 밖의 점, 5~10cm 사이의 애매한 점은 버립니다. 차체 자신에 찍힌 점(차체 둘레 0.1m 안)도 뺍니다. 바닥 점은 계산을 줄이려고 2개 중 1개만 씁니다.
예시 (같은 순간, 앞 카메라 1.9만 점): 장애물 219개 · 바닥 8,876개 · 버림 10,105개
천장 쪽 픽셀 (30.5, 20.5), Z = 11.2m → 높이 10.0m, 거리 16.8m → 버림

464×64 지도로 — 칸 번호 계산과 칠하는 규칙

지도는 AGV를 기준으로 한 64×64 칸, 한 칸 0.15m입니다(9.6m × 9.6m). AGV 기준점은 위에서 44번째 줄, 가로 한가운데(32번 열 경계)에 있어서 앞 6.6m · 뒤 3.0m · 좌우 4.8m를 봅니다. 앞이 위쪽입니다.

\[ r = \left\lfloor\, 44 - \frac{x_f}{0.15} \,\right\rfloor,\qquad q = \left\lfloor\, 32 - \frac{x_l}{0.15} \,\right\rfloor,\qquad 0 \le r,\, q \le 63 \ \text{만 씀} \]
쉬운 말앞으로 0.15m 갈 때마다 한 줄 위, 왼쪽으로 0.15m 갈 때마다 한 칸 왼쪽입니다. \(\lfloor\ \rfloor\)는 소수점 아래 버림입니다. 범위 밖(예: 7m 앞)이면 지도에 안 들어갑니다.
예시: 2장의 사람 점 (앞 2.07, 왼쪽 −0.32)
r = ⌊44 − 2.07/0.15⌋ = ⌊44 − 13.8⌋ = 30, q = ⌊32 − (−0.32)/0.15⌋ = ⌊32 + 2.13⌋ = 34 → 30번 줄 34번 칸이 초록
바닥 점 (앞 0.66, 왼쪽 0) → r = 39, q = 32 → 파랑

질문: 칸 안에 점이 조금만 있어도 칠하나요, 일정 비율 이상일 때만 칠하나요?

점이 하나라도 떨어지면 칠합니다. 비율이나 개수 문턱은 없습니다. 칸마다 "있다(255) / 없다(0)" 두 가지뿐이고, 점이 몇 개였는지는 남기지 않습니다.

\[ G[r,q] = 255\cdot\mathbf{1}\big[\exists\ \text{obstacle point } i:\ (r_i, q_i) = (r, q)\big] \] \[ B[r,q] = 255\cdot\mathbf{1}\big[\exists\ \text{floor point } j:\ (r_j, q_j) = (r, q)\big] \]

\(\mathbf{1}[\cdot]\) = 괄호 안이 참이면 1, 거짓이면 0. \(\exists\) = "하나라도 있다".

  • 채널 세 장: R = 처음 지도의 랙·벽(모델 입력에서는 끔, 모두 0) · G = 장애물 · B = 바닥. 같은 칸에 둘 다 있으면 G와 B가 함께 켜져 하늘색으로 보입니다(예: 사람 다리 사이로 바닥이 보일 때).
  • 카메라 4대: 네 카메라의 점을 모두 합친 뒤 한 번에 칠합니다.
  • 검정: 점이 하나도 없는 칸. "안 보이는 곳"이거나 5m 밖입니다.
  • Dreamer에 넣을 때: 값을 255로 나눠 0 또는 1로 넣습니다. 지도는 0.2초마다 새로 만들고, 이전 지도를 이어 붙이지 않습니다(이어 기억하는 일은 Dreamer의 기억 \(h\)가 합니다).
왜 문턱이 없나시뮬레이터 깊이에는 잡음이 없어서 잘못 찍힌 점이 없습니다. 또 가까운 칸에는 점이 수십 개 떨어지지만 먼 칸에는 한두 개뿐이라, "몇 개 이상"으로 자르면 먼 장애물이 사라집니다. 실제 카메라로 가면 잡음 점이 생기므로 "2개 이상"이나 "몇 장 연속" 같은 걸러내기를 넣어야 합니다.

헷갈리기 쉬운 것: 길찾기(A*)용 지도는 다른 지도이고, 거기에는 문턱이 있습니다. 같은 0.1m 칸에서 장애물을 10번 연속(1초) 봐야 "확정 장애물"로 지도에 넣습니다(10장). Dreamer 입력 지도는 매 순간 본 그대로이고, 길찾기 지도는 확실한 것만 쌓아 둔 지도입니다.

5행동 입력 — 전진 속도와 회전 속도

\[ a_t = (\bar v_t,\ \bar\omega_t) = \frac{1}{n}\sum_{\text{0.2 s}} (v, \omega),\qquad \tilde a_t = \left(\frac{\bar v_t}{1.0},\ \frac{\bar\omega_t}{1.2}\right) \]
쉬운 말그 0.2초 동안 AGV에 준 명령의 평균입니다. \(v\)는 앞으로 m/s, \(\omega\)는 초당 몇 라디안 도나(+ 왼쪽, − 오른쪽, 1rad ≈ 57°). 두 값의 크기를 비슷하게(대략 −1~1) 맞추려고 회전만 1.2로 나눠 넣습니다. 각도가 아니라 도는 빠르기입니다.

좌우 바퀴 속도는 이 두 값에서 바로 나옵니다(바퀴 사이 \(L = 0.579\)m, 바퀴 반지름 0.081m).

\[ v_L = v - \frac{\omega L}{2},\qquad v_R = v + \frac{\omega L}{2},\qquad \text{wheel speed} = \frac{v_{L,R}}{0.081}\ \text{rad/s} \]
실제 기록\((v, \omega)\)모델 입력뜻
빠른 직진(0.92, 0.00)(0.92, 0.00)0.92m/s로 곧게
돌며 전진(0.50, 0.25)(0.50, 0.21)초당 14° 왼쪽. 왼바퀴 0.43, 오른바퀴 0.57m/s
제자리 회전(0.00, 0.72)(0.00, 0.60)서서 초당 41° 왼쪽
정지(0.00, 0.00)(0.00, 0.00)

예: "1m/s로 가며 초당 30° 오른쪽" = \((1.0,\ -0.52)\) → 모델 입력 \((1.0,\ -0.44)\).

6Dreamer 구조 (RSSM)

DreamerV3의 월드모델 구조를 그대로 쓰고, 우리 데이터로 처음부터 학습했습니다. 전체 1,450만 개 숫자(14,504,324개 · 58MB).

\[ e_t = \mathrm{enc}(x_t) \qquad\qquad \text{(encoder: 64×64 map} \to \text{numbers)} \] \[ h_t = \mathrm{GRU}\big(h_{t-1},\ z_{t-1},\ \tilde a_{t-1}\big) \qquad \text{(memory, 512)} \] \[ z_t \sim q(z_t \mid h_t, e_t) \qquad\qquad \text{(posterior: after seeing)} \] \[ \hat z_t \sim p(\hat z_t \mid h_t) \qquad\qquad\ \ \text{(prior: before seeing = imagination)} \] \[ \hat x_t = \mathrm{dec}(h_t, z_t),\qquad c_t = \sigma\big(\mathrm{head}(h_t, z_t)\big),\qquad p_t = 1 - c_t \]
부품쉬운 말
인코더 \(\mathrm{enc}\)지도 한 장을 작은 숫자 묶음으로 줄이는 합성곱 신경망
기억 \(h_t\)지난 상태와 행동을 계속 쌓는 순환 신경망(GRU). 지도 한 장에는 없는 움직임(사람이 다가오는 중인지)을 여기서 압니다
요약 상태 \(z_t\)32개 문항 × 각 32지선다의 객관식 답안. "본 뒤"(\(q\))와 "보기 전 예측"(\(p\)) 두 가지로 만듭니다
상상 \(p\)지도를 안 보고 기억만으로 다음 \(z\)를 고름. 주행 중 미래를 굴려 볼 때 이것만 씁니다
디코더 \(\mathrm{dec}\)\(h, z\)로 지도를 다시 그림. 요약이 지도 내용을 담았는지 학습할 때 확인용
충돌 머리 \(c_t\)원래 "에피소드가 계속되나" 확률. 우리는 충돌하면 끝나게 데이터를 만들어서 \(p_t = 1 - c_t\)가 곧 그 칸에서 부딪힐 확률입니다
\[ q = 0.99\cdot\mathrm{softmax}(\ell) + 0.01\cdot\tfrac{1}{32} \]
쉬운 말객관식 답의 확률에 1%는 "아무거나"를 섞어서, 어떤 답도 확률 0이 되지 않게 합니다(학습이 한쪽으로 굳지 않게). 객관식 형태라서 "멈출 수도, 계속 걸을 수도" 같은 여러 미래를 한 번에 담고, 뽑을 때마다 다른 미래가 나옵니다.

7학습 — 무엇을 줄이나

\[ \mathcal{L} = \underbrace{\sum_{\text{pixels}} (\hat x_t - x_t)^2}_{\text{(A) map}} \;+\; 2\cdot\underbrace{\mathrm{BCE}(c_t, y_t)}_{\text{(B) collision}} \;+\; 0.5\cdot\underbrace{\max\!\big(1,\ \mathrm{KL}[\,\mathrm{sg}(q)\,\|\,p\,]\big)}_{\text{(C) imagination}} \;+\; 0.1\cdot\underbrace{\max\!\big(1,\ \mathrm{KL}[\,q\,\|\,\mathrm{sg}(p)\,]\big)}_{\text{(D)}} \] \[ \mathrm{BCE}(c, y) = -\big[\,y\log c + (1-y)\log(1-c)\,\big],\qquad y_t = \begin{cases} 0 & \text{collision at } t \\ 1 & \text{otherwise} \end{cases} \] \[ \mathrm{KL}[\,q\,\|\,p\,] = \sum_{\text{32 slots}}\ \sum_{k=1}^{32} q_k \log\frac{q_k}{p_k} \]
항쉬운 말
(A) 지도 복원다시 그린 지도와 실제 지도의 칸별 차이의 제곱 합(0~1 값으로). 요약 \(z\)가 지도를 잘 담게 만듭니다
(B) 충돌 ×2부딪힌 칸이면 \(c\)를 0으로, 아니면 1로 맞히게 합니다. 충돌이 드물어서 2배 무게
(C) 상상 맞추기 ×0.5"보기 전 예측" \(p\)를 "본 뒤 상태" \(q\)에 가깝게 당깁니다. 이 항 덕분에 안 보고도 다음을 맞히게 됩니다. \(\mathrm{sg}\)(기울기 멈춤)는 이 항이 \(p\)만 움직이게 한다는 뜻
(D) ×0.1반대로 \(q\)가 예측하기 어려운 쪽으로 너무 멀어지지 않게 살짝 잡아 둠
\(\max(1,\cdot)\)차이가 1 이하면 더 줄이려 애쓰지 않음("이미 충분히 비슷하면 그만")

학습 데이터와 설정

  • Isaac Sim 창고 9곳, 2,305번 주행(0.2초 칸 53만 5천 개, 약 30시간, 충돌 752번). 그중 231번은 검증용으로 빼고 2,074번으로 학습. 운전 방식: 규칙대로 피하기 35% · 속도 무작위 50% · 피하지 않기 15%. 길이 없는 장면은 뺐습니다.
  • 한 번 학습에 16조각 × 24칸(4.8초). 충돌로 끝난 주행을 뽑으면 30% 확률로 "충돌 순간이 든 마지막 4.8초"를 잘라 씁니다(드문 충돌을 자주 보게).
  • Adam, 학습률 \(10^{-4}\), 40,000번 반복, RTX 5090에서 76분. 주행 번호 끝자리 0인 10%는 검증용으로 빼 두고, 검증 AUROC가 가장 좋은 22,000번째(0.948)를 씁니다.

8상상 → 위험 → 속도 고르기 (0.2초마다)

① 보기: 새 지도 \(x_t\)와 방금 행동 \(\tilde a_{t-1}\)로 \(h_t, z_t\)를 갱신합니다(6장의 식). ② 상상: 속도 후보 5개마다 앞으로 10칸(2초)의 행동열을 만들고, 지도 없이 \(p\)만으로 굴립니다.

\[ v \in \{1.0,\ 0.6,\ 0.3,\ 0,\ -0.3\},\qquad \text{for each } v:\ \ S = 8 \text{ samples},\ \ k = 1..10 \]
쉬운 말앞으로 가는 후보는 "지금 경로를 그 속도 이하로 따라가면" 나오는 10칸의 행동(\(v,\omega\))이고, 0과 후진은 곧게입니다. 같은 후보도 미래가 여러 가지일 수 있어서 8번씩 상상합니다.

③ 2초 안에 한 번이라도 부딪힐 확률:

\[ P^{(s)}(v) = 1 - \prod_{k=1}^{10}\big(1 - p^{(s)}_k\big),\qquad \bar P(v) = \frac{1}{8}\sum_{s=1}^{8} P^{(s)}(v) \]
쉬운 말"10칸 내내 안 부딪힐 확률"은 칸마다 안 부딪힐 확률을 모두 곱한 것입니다. 1에서 빼면 "한 번이라도 부딪힐 확률"입니다. 예: 칸마다 2%면 \(1-0.98^{10} \approx 18\%\).

④ 보정(Platt): 학습 때 충돌에 2배 무게를 주고 충돌 조각을 많이 보여 줘서, 모델이 낸 확률은 실제보다 큽니다. 검증 데이터로 맞춘 식으로 실제 비율에 맞춥니다.

\[ P_{\text{cal}} = \sigma\big(a\cdot\mathrm{logit}(\bar P) + b\big),\qquad a = 0.515,\ \ b = -1.853,\qquad \mathrm{logit}(p) = \ln\frac{p}{1-p},\ \ \sigma(z) = \frac{1}{1+e^{-z}} \]
모델이 낸 \(\bar P\)0.100.200.500.900.99
보정 후 \(P_{\text{cal}}\)4.8%7.1%13.6%32.7%62.6%

⑤ 고르기:

\[ v^* = \max\,\{\, v \;:\; P_{\text{cal}}(v) \lt 0.05 \,\} \] \[ \text{if none:}\quad v^* = \arg\max_v\ \bar t(v),\qquad \bar t = \sum_{k=1}^{10} 0.2k\; p_k \prod_{j\lt k}(1-p_j) \;+\; 2.2\prod_{k=1}^{10}(1-p_k) \]
쉬운 말위험 5% 미만인 속도 중 가장 빠른 것으로 갑니다. 모두 위험하면 "부딪히기까지 가장 오래 버티는" 속도를 고릅니다(\(\bar t\) = 충돌까지 기대 시간, 끝까지 안 부딪히면 2.2초로 셈).
예시 (애니메이션의 순간, 실제 모델 출력): 1.0m/s 23% · 0.6m/s 2.3% · 0.3·0·후진 0.1% → 5% 미만 중 가장 빠른 0.6m/s 선택

⑥ 다른 제한과 합치기: 실제 속도는 경로 추종이 원하는 속도, Dreamer가 고른 \(v^*\), 규칙 제한 중 가장 낮은 값입니다. 줄일 때는 곡률이 같게 \(\omega\)도 같은 비율로 줄입니다.

\[ v_{\text{cmd}} = \min\big(v_{\text{path}},\ v^*,\ v_{\text{rule}}\big),\qquad \omega_{\text{cmd}} = \omega_{\text{path}}\cdot\frac{v_{\text{cmd}}}{v_{\text{path}}} \]
  • 규칙 제한(혼합 방식): 앞 1.5m 정지 구역은 그대로, 감속은 "확정 안 된 물체가 앞 2.5m(옆 1.2m) 안이면 0.6m/s까지".
  • 교착 탈출: Dreamer가 4초 넘게 정지만 고르고 1.5m 정지 구역이 비어 있으면 0.3m/s로 지나갑니다.
  • 판단 지연: 계산에 걸린 시간만큼 늦게 적용합니다. \(n_{\text{apply}} = n + \lceil \text{ms}/1000 \times 30 \rceil\) (30 = 1초당 물리 계산 횟수). 한 번 판단 0.11초(5090), 0.044초(Jetson Orin).

9규칙(비교 대상)

차체 앞면에서 앞으로 \(u\), 옆으로 \(s\)만큼 떨어진 장애물 점(확정된 지도 장애물은 빼고)을 봅니다. 차체 반폭은 0.33m입니다.

\[ v_{\text{rule}} = \begin{cases} 0 & \exists\ \text{point}:\ -0.3 \lt u \lt 1.5,\ |s| \lt 0.33 + 0.8 \\ 0.35 & \exists\ \text{point}:\ -0.3 \lt u \lt 3.0,\ |s| \lt 0.33 + 1.2 \\ \infty & \text{otherwise} \end{cases} \]
쉬운 말앞 1.5m(옆으로 차체 바깥 0.8m까지) 안에 무언가 있으면 정지, 3m 안이면 0.35m/s로 감속. 지금 위치만 보고 상대가 다가오는지는 모릅니다. 1.5m 앞 사람이 1.4m/s로 다가오고 AGV가 1m/s면 닿기까지 \(1.5 / (1.4 + 1.0) \approx 0.6\)초.

10길찾기 — A*와 경로 따라가기

\[ f(n) = g(n) + h(n),\qquad g(n') = g(n) + d\,\big(1 + \text{extra}(n')\big),\qquad d \in \{1, \sqrt 2\}\ \text{cells} \] \[ \text{extra} = 4\cdot\max\!\Big(0,\ \frac{1.5 - \text{dist}}{1.5}\Big),\qquad \text{forbidden if dist} \lt 0.7\ \text{m},\qquad h(n) = \text{straight-line distance to goal} \]
쉬운 말0.1m 칸 지도에서 8방향으로 넓혀 가며, "온 거리 \(g\) + 남은 직선거리 \(h\)"가 가장 작은 칸부터 봅니다. 직선거리는 실제 남은 거리보다 길 수 없어서 가장 짧은 길을 놓치지 않습니다. 장애물에서 0.7m 안 칸은 못 가고, 1.5m 안 칸은 비용을 더 매겨 통로 가운데로 다니게 합니다(dist = 가장 가까운 장애물까지 거리).

경로 따라가기(Pure Pursuit): 경로 위 0.8m 앞 점을 AGV 기준 \((x_r, y_r)\)로 보고,

\[ \kappa = \frac{2\,y_r}{x_r^2 + y_r^2},\qquad v_{\text{path}} = \min\!\Big(\frac{1.0}{1 + 2|\kappa|},\ \max(0.2,\ d_{\text{goal}})\Big),\qquad \omega_{\text{path}} = \mathrm{clip}\big(v_{\text{path}}\,\kappa,\ -1.2,\ 1.2\big) \]
쉬운 말두 바퀴 로봇은 속도·회전이 일정하면 원을 그립니다. 0.8m 앞 점을 지나는 원의 굽은 정도 \(\kappa\)(곡률 = 1/반지름)를 구해 그만큼 돕니다. 많이 굽을수록 느리게, 목적지 가까이서도 느리게 갑니다.

본 장애물을 지도에 넣기(확정 카운터): 0.1m 칸마다 숫자 \(H\)를 둡니다(0.1초마다 관측).

\[ H \leftarrow \begin{cases} \min(H + 1,\ 20) & \text{obstacle points in the cell} \\ \max(H - 5,\ 0) & \text{only floor points in the cell} \end{cases}\qquad \text{confirmed if } H \ge 10 \;\Rightarrow\; \text{re-plan A*} \]
쉬운 말같은 칸에 장애물이 약 1초(10번) 계속 보여야 확정하고, 그 자리에서 길을 다시 찾습니다. 바닥이 다시 보이면 빠르게 지웁니다. 지나가는 사람은 확정되지 않아 길을 바꾸지 않고, 떨어진 상자처럼 머무는 것만 지도에 들어갑니다.

11평가 숫자의 식

  • 충돌 없이 도착: 150초 안에 목적지 칸(0.3m 안)에 도착하고, 그동안 한 번도 닿지 않음.
  • 제시간 도착: \(T_{\text{arrive}} \le L_{\text{path}} / 0.7 + 10\) 초 (\(L_{\text{path}}\) = 처음 계획한 경로 길이).

짝 비교(McNemar 정확 검정): 같은 장면에서 결과가 갈린 경우만 셉니다. \(b\) = 규칙만 성공, \(c\) = Dreamer만 성공.

\[ p = \min\!\Big(1,\ 2\sum_{i=0}^{\min(b,c)} \binom{b+c}{i}\, 2^{-(b+c)}\Big) \]
충돌 없이 도착: \(b = 13,\ c = 26\) → \(p = 0.053\) (경계선) · 제시간: \(b = 17,\ c = 47\) → \(p = 0.0002\)
쉬운 말둘이 실력이 같다면 갈린 39번은 동전 던지기처럼 반반이어야 합니다. 13 대 26처럼 치우칠 확률이 \(p\)입니다. 5%보다 작으면 "우연이라 보기 어렵다"고 말합니다.

AUROC (충돌 예측 시험):

\[ \text{AUROC} = P\big(\,\text{score}(\text{positive}) \gt \text{score}(\text{negative})\,\big) \]
쉬운 말"2초 안에 실제로 부딪힌 순간"(양성) 하나와 "부딪히지 않은 순간"(음성) 하나를 무작위로 골랐을 때, 위험 점수가 양성 쪽이 더 높을 확률입니다. 1이면 완벽, 0.5면 찍기. Dreamer의 점수는 ③의 \(P\)(실제 행동으로 상상), 비교용 점수는 앞 통로(앞 0~4m, 좌우 0.8m)에서 가장 가까운 초록 칸까지 거리(가까울수록 위험)입니다.

누가 먼저 도착했나(부호 검정): 둘 다 도착한 480번 중 334번 Dreamer가 먼저 → \(p = 2\,P(X \ge 334 \mid n = 480,\ 0.5) \lt 10^{-18}\).

12알아 둘 한계

  • 후진 데이터가 적음: 최종 학습 데이터 53만 5천 칸 중 후진(\(v \lt 0\))은 2,974칸(0.6%), 대부분 좁은 곳에서 빠져나올 때의 −0.25~−0.3m/s 후진입니다. 후보 "후진 0.3"의 위험은 다른 속도보다 덜 정확할 수 있습니다.
  • 칠하기 문턱 없음: 시뮬레이터 깊이는 잡음이 없어서 괜찮지만, 실제 카메라에서는 잡음 점·빈 값(0) 처리가 필요합니다.
  • 카메라 차이: 시뮬레이터 감지 카메라는 가로 120°, 실제 D435·D455는 약 87°.
